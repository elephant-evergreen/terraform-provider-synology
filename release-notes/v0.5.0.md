## Breaking changes

### Shared-folder rename and volume changes are refused at plan time

`synology_shared_folder` previously planned a replacement when `name` or `volume` changed. Applying that plan with `deletion_protection = false` deleted the existing folder and its files.

The provider now rejects the change during plan and asks for an explicit migration: create a new shared folder and move the data, or release management with a `removed` block using `destroy = false`. Existing configurations and state need no changes.

## Upgrade notes

Existing configurations and state need no changes unless they contain a shared-folder rename or volume change, which now fails during plan as described above.

The provider records the NAS serial number in each resource's private state on create, read, update, and import. The first refresh after the upgrade binds existing state; a state bound to a different NAS is refused instead of applied.

## Highlights

- Every resource refuses to read or change state bound to another NAS serial. When a DSM version does not advertise `SYNO.Core.System`, the binding is skipped with a warning and the object-level identity checks remain.
- Shared-folder, group, and user identity checks now run in the same mutation lock as the write and readback. Permission updates already held the lock and now apply reductions and explicit denies before grants.
- An unacknowledged user password write is recorded in private state and is not replayed. Rotate again with a higher `password_version` or re-import the account.
- A partially applied permission policy is recorded in private state. Re-apply the same policy, or re-import the shared folder before applying a different one.
- Shared-folder creation checks that the name is absent and creates it in one locked operation.

## Compatibility

Fixture tests cover the new behavior. Hardware writes remain experimental: read and import behavior is verified on DSM 7.1.1, and write acceptance requires the dedicated environment described in [testing](https://github.com/elephant-evergreen/terraform-provider-synology/blob/v0.5.0/docs/testing.md#write-acceptance-environment).
